# Lab 持续生产与原矿回补

本次规则按用户确认：保留本房缺药优先；本房药齐后，持续生产全局库存最少的可合成 T3，不设全局库存上限。保留原有 3000 批次和其他房间在制数量，避免每 tick 改配方和所有房间同时选同一种药。

## 官服检查

shard3，83580529–83580849 的库存、Lab 原料槽、搬运队列和原生 cooldown 只读快照：

- 七个普通房间的 X 原料 Lab 为空：E34N3、E35N1、E35N3、E36N2、E39N6、E41N7、E41N8。各房 X 总量恰为 10000，属于已有基础矿常备量，Processor 可搬数量为 0。
- E37N7、E38N5 的本房矿物都是 X，已有约 15k、48k；它们能供自己的 Lab 使用，但未达到本地产矿 300k 外发保留线，不能支援其他房间。这两房的反应量持续减少、输出库存增加，属于正常工作。
- 仓库 E38N6 原矿 X 合计 7000；已有手工 X 10000 外发任务占用这部分库存。purifier 有 55960，但旧 Factory 仅合成商品或压缩，不会还原原矿。
- 十个房间均有 10 个 Lab、有效原料 Lab 配置；没有待 Boost 请求、强制暂停或终端接收容量不足。CPU bucket 接近 10000，房间规划与末阶段持续执行。

因此，主要资源卡点是可调拨的原矿 X 枯竭，并非达到 T3 库存上限。旧全局选品分支本来就没有使用 legacy reactionConfig 中的库存上限。

## 修改

1. Lab 先尝试本房不足 20000 的 T3；如果本房缺药全部缺料，继续尝试其余 T3，按全局库存从少到多选择。原先此时会直接清空计划停工。原料补齐后，本房缺药重新抢占全局批次。
2. Factory 保持可合成商品优先；无商品可合成时，仓库将已有压缩矿还原，补足既有 300000 原矿保留线，再处理原矿超量压缩。支持全部基础矿和 G 的合法逆配方，不绑定 X 或房间名。
3. 解压批次受原矿缺口、实际原料、能量、Factory 容量和原生 cooldown 限制；执行时再次核实仓库资格与保留线。新商品可立即抢占解压。已有 Boost、Lab、外发预留与终端 50000 能量保护继续适用。
4. 解压目标按全房库存计数，包括 Lab 和 manager/processer 携带的产物；可用生产原料的旧计算保持不变。最后一批最多多补 499，不能立刻凑足一次反向压缩，运输途中也不会重复补产。

没有延长 Lab、Factory 或搬运任务的运行间隔。配方、原料量与解压目标读数复用单次规划缓存。原生生产仍遵循 [Screeps Factory API](https://docs.screeps.com/api/#StructureFactory.produce) 的原料、容量、等级和冷却约束；原料进入 Factory 后才会执行生产。
