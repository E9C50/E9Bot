# 资源调度与生产

资源策略集中在 `src/settings/resourcePolicy.ts`，自动调度由 `room/resourceNetwork.ts` 统一处理。统计包含 Storage、Terminal、Lab、Factory 和本地 Manager/Processer 货物；运输中的承诺、已提交发送和手续费独立记账，避免同 tick 重复承诺。当前 shard 的房间共享终端网络，跨 shard 仍使用已有专门运输任务。

## 普通房与仓库

启用 Power（`controller.isPowerEnabled`）且实际 Storage 容量至少 8000000 的自有房是仓库。判断容量而不是已存数量；1M Storage 即使启用 Power 仍是普通房。撤离房不参与正常生产和调度。

| 资源 | 普通房库存目标 / 余量规则 |
| --- | --- |
| 十种 T3 | 每种补到 20000，超额送仓库 |
| H、O、U、L、K、Z、X | 每种补到 10000，生产也保护该底线 |
| G | 补到 10000，生产也保护该底线 |
| OPS | 补到 5000，超额送仓库 |
| T1、T2、OH、ZK、UL | 不主动补齐，现有库存最多留 20000；生产可直接消耗 |
| Power | 延续原策略留 3000，余量送仓库 |
| 商品、压缩矿 | 留当前生产批次及下一合法商品所需已有前置，余量送仓库 |

先满足普通房短缺，再把普通房余量直接分给该资源库存最低的仓库，减少中转。仓库按每种资源的预计库存均衡，预计库存包括已承诺入库/出库；容差为平均库存的 1%，最低 1、最高 1000，使小批量商品也能均分。没有可用仓库时保留余量；普通房仍可互相补缺。

## 终端与 Manager

全房资源规划每 30 tick 执行一次，各房每 tick 处理发送与备货。终端只准备下一笔可发送批次，默认单次最多 100000，按源房可用库存、终端冷却、交易手续费、发送端容量与目标终端本 tick 已预约容量缩减批次。能量货物同时计算货物与手续费，发送后至少留下 50000 能量。有效的 `PWR_OPERATE_TERMINAL` 费用减免计入计算；不足以付费时先搬入额外能量。

Manager 默认 49 CARRY + 1 MOVE，共 50 部件、2500 能量。成熟房按能量容量规划并等待足够出生能量，发展期仍按发展预算配置。无 Filler 且 Storage 有能量时先补紧急 Filler，以免大 Manager 等待期间无人填充 Spawn。已存活的小 Manager 自然替换，自定义身体配置继续有效。

终端不足时先补能量；占满时清出不需要的货物，按实际缺口限量搬运。Manager、Factory 物流和跨房发送共享目标终端容量预约；发送/市场成交后的有效终端余额立即扣除货物和手续费，后续搬运不使用未结算的旧 Store 数量。

显式发送任务保留，失败任务记录 `lastError`、`failures`、`retryAfter` 并退避重试；等待期间不霸占备货。自动任务包含 `kind`，库存减少或目标失效时裁减不能兑现的承诺，使接收房可以寻找新供给。

## Lab 与 Factory

Lab 优先本房短缺 T3；无短缺时生产全局库存最低且原料可满足的 T3。仓库参与全局生产，其他房在产批次也计入选品，避免全部房间同时追逐同一资源。默认稳定批次 3000；有强化 Lab 时按实际反应单位向上取整。递归规划优先分配本房/仓库已有 T1、T2，已有化合物不重新拆成基础矿合成。基础矿/G 底线与 Boost、Factory 预留从可用原料中扣除，跨房申请使用绝对库存目标并计入已有入库承诺。

`productionPlan.remaining` 按最终 T3 成功反应的实际产量递减，产物出口不会扩大或重开全局批次；前置反应不扣最终批次。Processer 取料同时限制生产缺口、工人容量与源库存，只在原生取料成功后切换运送状态。

Factory 原实现为空，现在按本房 Storage、Terminal、Factory 和在途工厂货物选品。优先原料足够的商品，较高合法等级优先、同级看全局库存；永久等级与有效 `PWR_OPERATE_FACTORY` 同时检查。无可做商品时仅压缩本房 Mineral，保护基础矿底线、Lab/Boost 预留及既有发送承诺。批量受 20 次、500 tick 与 Factory 容量共同限制；冷却时继续备料和清货。Manager 只处理座位附近的工厂，移动 Processer 补充其他位置的物流，RCL7 的 Factory 也会发布 Processer。

工厂物流先凑齐下一轮输入，保留厂内可直接使用的多余燃料，容量不足时只清出所需空间；待入厂任务与同 tick 已提交的转移共同预约 Factory 容量。
